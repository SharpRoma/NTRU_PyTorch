feat(research): перенести NTRU на Ubuntu и Raspberry Pi и добавить liboqs

Развить экспериментальный конвейер из 14c24e7 до точного аппаратно
проверенного NTRU и воспроизводимых сравнений с внешними CPU-ядрами.

- Адаптировать DFC 3.33.0 под Ubuntu 24.04 и Python 3.12, добавить
  установку Linux HailoRT/DKMS с проверкой происхождения компонентов.
- Извлекать реальные численные параметры SDK и допускать affine HEF
  с рациональной границей ошибки строго меньше 1/2 без ослабления unit-контракта.
- Добавить active16-v1, кэш точной LUT и оптимизированную обработку
  данных на CPU, сохранив прежние API, форматы и значения по умолчанию.
- Добавить SparseNTRU и два независимых интерфейса liboqs 0.16.0:
  циклическое Rq-ядро в нашем протоколе и публичный NTRU-HRSS-701 KEM.
- Подготовить закреплённые clean/AVX2 сборки, C-мосты, ctypes,
  KAT, проверки совместимости и раздельные процессные бенчмарки.
- Сократить память допуска артефактов потоковым чтением свидетельств
  и добавить отдельный NumPy-only runtime-wheel без Torch и SymPy.
- Подтвердить точность N17/N107/N701 на Hailo-8L на ПК и N701
  на Raspberry Pi 5 1 ГБ, включая 2500 проб и восстановление сессии.
- Зафиксировать настройку DMA 4096 для 16-КиБ страниц ядра Pi,
  исходные отчёты, пределы выводов, инструкции и контекст для продолжения.

На ПК OQS AVX2 быстрее Hailo по полному шифрованию N701 на проверенных
партиях. KEM измеряется отдельно; ARM liboqs и скорость на Pi ещё не проверены.

Проверки: полный программный набор без hardware-marked теста, Ruff,
синтаксис shell/Python; отдельные реальные аппаратные отчёты ПК и Pi.
Ключи, HEF, окружения, vendor checkout и тяжёлые результаты остаются вне Git.
