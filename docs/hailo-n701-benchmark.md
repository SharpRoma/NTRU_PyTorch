# Производительность NTRU N=701 на Hailo-8L

> Исторический бенчмарк reference host. Для текущих CPU-ориентиров и Raspberry Pi см. [актуальный handoff от 9 ноября 2026](CODEX_HANDOFF_2026-11-09.md): OQS/Sparse быстрее Hailo на проверенных партиях ПК, скорость Pi ещё не измерена.

Аппаратный запуск 8 ноября 2026 завершён успешно. В этом запуске Hailo быстрее текущего PyTorch CPU на всех проверенных партиях. Вывод относится к существующему алгоритму проекта, этому ключу и HEF, предварительно подготовленным r и открытой аппаратной сессии.

## Условия и точность

- Каталог: `results/n701-benchmark-2026-11-08-001/`; предыдущие результаты сохранены.
- Артефакт: `results/admitted-n701-ubuntu-affine-001`; ключ: `results/compiler-experiments/n701-active16-2026-11-08/private.json`.
- N=701, p=3, q=8192, d=55; `active16-v1`, кэш точной LUT, seed=42, 6 потоков PyTorch, 3 прогрева и 20 измерений на backend и размер партии.
- HAILO8L, PCIe `0000:25:00.0`, HailoRT/PyHailoRT и firmware 4.23.0; DFC артефакта 3.33.0. Python 3.12.3, PyTorch 2.15.0, NumPy 1.26.4, ядро 7.0.0-42-generic.
- HEF SHA256: `a8db2b54e0eb7f519959f808f1c0312bc820567eb5bf95e7a40cc01617b6af63`.
- Канонический SHA256 публичного ключа: `54e0c7e244eb1c93c4761b4b99a98e0e8123a13f17663754931650ca08042f03`.

Перед измерениями повторно проверены контрольные суммы всех файлов manifest и выполнены **2500 аппаратных проб**, включая **1000 случайных полиномов** и граничные входы: точные частичные суммы и восстановленное произведение. Для каждой партии подтверждены одинаковые шифротексты SymPy/PyTorch/Hailo и расшифровка результата Hailo обоими CPU-backend. `cli-report.json`: `status=passed`, `hardware_tested=true`; в `benchmark.json`: `validation.stage=hardware`, `exact=true`.

SymPy исключён только из прогревов и измерений, его проверки правильности сохранены. Сообщения и r подготовлены заранее и одинаковы для обоих измеряемых backend. Полное время охватывает `encrypt_bytes` с явными r, кодирование сообщения, проверки API и восстановление шифротекста. Генерация ключей/r, расшифровка, загрузка артефакта и файловый ввод-вывод в основной таймер не входят. Порядок CPU/Hailo чередуется. Программные тесты и компиляция во время измерений не запускались.

Медианы отдельных фаз не обязаны складываться в медиану полного времени. SDK + PCIe не является измерением внутреннего времени NPU.

## Старт и сравнение с N=107

Проверка/чтение артефакта вместе с численным доказательством заняли **53.238 с**, открытие аппаратной сессии вместе с загрузкой HEF и построением LUT — **0.138 с**. Сумма — **53.376 с**. Это старт Hailo-движка в уже запущенном Python после чтения приватного ключа; очистка файлового кэша ОС не выполнялась. Эти расходы исключены из таблицы шифрования. Сессия должна переиспользоваться, чтобы наблюдаемое ускорение не перекрывалось проверкой артефакта при каждом открытии.

Историческое время компиляции с размещением **83.213 с** перенесено из manifest как метаданные; в этом эксперименте компиляция не выполнялась.

Сравнение с отдельным контролируемым запуском `results/optimization-2026-11-08/n107-variants-controlled.json`, тоже с 6 потоками и выбранным `active16-v1` + LUT:

| Показатель на 128 блоках | N=107 | N=701 |
|---|---:|---:|
| Полезное сообщение, байт | 1704 | 11208 |
| PyTorch CPU, мс | 42.123 | 381.979 |
| Hailo, мс | 30.011 | 265.695 |
| CPU/Hailo | 1.404× | 1.438× |
| Hailo, полезных байт/с | 56 780 | 42 184 |
| Кадров | 256 | 1024 |
| Вход + выход, байт | 196608 | 10059776 |
| Упаковка, мс | 7.055 | 39.960 |
| SDK + PCIe, мс | 6.365 | 28.582 |
| Affine decode, мс | 0.409 | 28.933 |
| Восстановление/редукция, мс | 3.663 | 90.219 |

N=701 переносит примерно в 6.58 раза больше полезных байт в такой партии, а VStreams payload вырос примерно в 51.17 раза. Относительное ускорение CPU/Hailo близко к N=107, но полезная пропускная способность Hailo ниже. Заметно выросли расходы CPU на декодирование и восстановление; на 128 блоках SDK-вызов занимает около 10.8% медианного полного времени. Это наблюдение по двум отдельным запускам, а не одновременно контролируемое сравнение разных N. Оно не доказывает причины различий или выгоду ещё не выполненных оптимизаций.

## Воспроизведение и файлы

Запускать в новом каталоге результатов после завершения других тестов и сборок:

```bash
cd /home/sharproma/PycharmProjects/NTRU_PyTorch
.venv/bin/python -m ntru_pytorch hailo-benchmark \
  --artifact results/admitted-n701-ubuntu-affine-001 \
  --private-key results/compiler-experiments/n701-active16-2026-11-08/private.json \
  --packing active16-v1 --skip-sympy-timing --torch-threads 6 \
  --seed 42 --runs 20 --warmup 3 \
  --output results/NEW-RUN/benchmark \
  --report results/NEW-RUN/cli-report.json
```

Новые параметры необязательны: без `--skip-sympy-timing` SymPy по-прежнему измеряется, без `--torch-threads` сохраняется прежняя настройка потоков. Установленное число потоков восстанавливается при завершении или исключении. Публичный API NTRU, упаковка и арифметика не менялись.

В каталоге запуска: `benchmark.json` и `.csv` — сырые измерения и метаданные; `summary.csv` — медианы/p95 и обе единицы пропускной способности; `phases.json/.csv` — медианы/p95 фаз; `preflight.json` — хеши, scan/identify и версии; `cli-report.json`, `checks.json`, `run.log`, `source-sha256.json` — подтверждение выполнения и диагностика. `benchmark.progress.json` показывает последнюю стадию и позволяет локализовать незавершённую попытку. При несовпадении точности или объёмов измерения прерываются.

Программные проверки: 66 passed, 1 аппаратный тест deselected; дополнительно прошёл тест CLI-параметров. Проверены сохранение SymPy-проверок вне таймера, число измерений, полезные байты/с, границы старта, установка и восстановление потоков, запрет перезаписи результатов и совместимость значений по умолчанию. Ruff и `git diff --check` прошли. Аппаратный вывод основан на описанном реальном запуске N=701. Энергопотребление не измерялось.
