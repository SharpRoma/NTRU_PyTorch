# Точная обработка NTRU на CPU вокруг Hailo

## Режимы и совместимость

`HailoEncryptor` и `SoftwareHailoEncryptor` принимают необязательный параметр `host_processing="reference" | "optimized"`. Значение по умолчанию — `reference`. В CLI ему соответствует `--host-processing`. Упаковка выбирается независимо через существующий `--packing`; кэш LUT включён по умолчанию.

Оптимизированный режим меняет обработку на CPU, сохраняя ключ, HEF, численное доказательство, входные кадры и шифротексты. PyTorch/SymPy, общий кодек и публичный `Ciphertext` не изменены. Ключ проверяется при каждом вызове; конструктор `Ciphertext` и его проверки сохраняются.

Изменения оптимизированного пути:

- Восстановление группирует подряд идущие кадры одного владельца и знака; суммы и битовые плоскости накапливаются в INT64. Расширение всего массива кадров до INT64 исключено. Для произвольно переставленной карты активных кадров сохраняется контрольный `np.add.at`. Позиционная упаковка использует прежний фиксированный смысл раскладки.
- Неизменяемая UINT8 LUT построена из прежней точной рациональной таблицы: суммы 0–16 сохраняются, остальные коды заменены маркером 255 и приводят к ошибке. Полный INT64 массив результатов декодирования больше не нужен. При включённом кэше таблица строится один раз на открытие сессии.
- Упаковщик предварительно вычисляет число кадров, выделяет конечные массивы и заполняет их по позициям коэффициентов. Порядок кадров, исходные номера каналов, нулевой кадр и неизменяемость массивов сохранены.
- Сообщение кодируется через `np.unpackbits(bitorder="big")` с прежним заголовком длины и заполнением. Публичные сообщения/r нормализуются один раз; неподходящие типы, bool, размеры и диапазоны отклоняются до сужения до INT64. Редукция и прибавление сообщения выполняются для всей партии; при `trace` используется последовательная ветвь с прежними событиями.

Для явно подготовленных r:

```python
with HailoEncryptor(artifact, packing="active16-v1", host_processing="optimized") as engine:
    ciphertext = engine.encrypt_bytes(public_key, message, r_polys=rs)
```

## Границы измерений

Существующие `prepare_ns`, `inference_with_io_ns`, `reconstruct_ns`, `pipeline_ns` и `encrypt_total_ns` сохранены. Дополнительные показатели разделяют кодирование сообщения, проверку ключа/нормализацию, проверку кадров, проверку выходов/карты, суммирование кадров, восстановление битовых плоскостей, редукцию и создание `Ciphertext`.

`reconstruct_ns` включает проверку выходов, суммирование, битовое восстановление и редукцию. `inference_with_io_ns` включает проверку кадров, affine encode, SDK + PCIe и affine decode. Внутри этих интервалов остаётся небольшой служебный расход Python. `unaccounted_ns` — остаток `encrypt_total_ns` после вычитания непересекающихся верхних фаз для каждого конкретного вызова. Внешнее `total_ns` также включает возврат из API. Иерархия сохранена в JSON; складывать вложенные фазы повторно нельзя. Медианы фаз не обязаны складываться в медиану полного времени.

Загрузка артефакта, численный допуск и открытие сессии измеряются отдельно. Внутреннее время NPU и энергопотребление не измеряются.

## Воспроизведение

```bash
cd /home/sharproma/PycharmProjects/NTRU_PyTorch
.venv/bin/python -m ntru_pytorch hailo-benchmark \
  --artifact results/admitted-n701-ubuntu-affine-001 \
  --private-key results/compiler-experiments/n701-active16-2026-11-08/private.json \
  --packing active16-v1 --host-processing optimized \
  --skip-sympy-timing --torch-threads 6 --seed 42 --warmup 3 --runs 20 \
  --output results/NEW-HOST-RUN/benchmark \
  --report results/NEW-HOST-RUN/cli-report.json
```

Для контрольного запуска заменить `optimized` на `reference` и выбрать новый каталог. Символьная проверка правильности сохраняется вне таймера. `--compare-variants` продолжает сравнивать упаковку/кэш при одном выбранном режиме CPU-обработки.

Программный диагностический микробенчмарк:

```bash
.venv/bin/python tools/benchmark_hailo_host.py \
  --artifact results/admitted-n701-ubuntu-affine-001 \
  --output results/NEW-HOST-MICRO.json
```

Он использует заранее вычисленные программные частичные суммы и **не подтверждает работу NPU**. Его нельзя выполнять параллельно с аппаратными замерами.

## Проверки

Программные тесты охватывают N=17/107/701, обе упаковки, знаки, нулевые/плотные/граничные входы, переставленные карты, отсутствующих владельцев, повторные группы знаков, повреждённые выходы и padding. Все 256 кодов LUT сверяются с точным эталоном; проверяются кодек, ошибки входов и трассировка. Адаптер отдельно проверяется с тестовым устройством для обоих режимов и включённого/выключенного кэша; эти тесты не являются аппаратными свидетельствами.

8 ноября 2026 оптимизированный путь последовательно прошёл реальную аппаратную квалификацию N=17 → N=107 → N=701. Проверены соответственно 1048/1238/2500 проб, в каждом случае минимум 1000 случайных полиномов; точные частичные суммы, произведения, шифротексты и кросс-расшифровка пустых, Unicode, бинарных и многоблочных сообщений. Для каждого N выполнены три открытия сессии и очистка после контролируемого исключения на хосте. Это не испытание восстановления после физической неисправности PCIe.

Граница нормализации r различается: в контрольном пути она входит в упаковку, в оптимизированном — в подготовку проверенных входов. Поэтому один `prepare_ns` не измеряет изолированное ускорение одного и того же участка. Сравнение полного времени и суммы подготовки/нормализации учитывает обе стороны. Проверки выхода и карты выполняются до группировки; проверки ключа и публичного результата сохранены.

Основные оставшиеся расходы — конструктор публичного `Ciphertext`, SDK + PCIe и affine-декодирование. Внутреннее время NPU отдельно не измерялось. Размеры передачи не изменились: 8 кадров на полином, на 128 блоках 1024 кадра, вход 720896 байт и выход 9338880 байт. Это размеры массивов VStreams, без накладных расходов PCIe; они проверены после каждого измеренного Hailo-вызова.
