# Упаковка активных коэффициентов NTRU на Hailo

Эксперимент 8 ноября 2026 года продолжает аппаратно проверенные N=17 и N=107. Существующие ключи, HEF и результаты 7 ноября сохранены. Secure Boot и TPM намеренно отключены пользователем и не являются предметом этого эксперимента.

## Изменения

Доступны два способа упаковки:

- `position16-v1` — прежние фиксированные группы по 16 соседних позиций; остаётся значением по умолчанию.
- `active16-v1` — ненулевые позиции каждого знака группируются максимум по 16 без изменения номеров входных каналов. Для штатного N=107 с d=5 это два кадра вместо четырнадцати. Полностью нулевой полином отправляет один нулевой кадр через настоящий аппаратный путь.

`BinaryScheme.pack_batch` возвращает кадры и карту владельцев/знаков. Восстановление по карте использует INT64. Прежние `pack` и `reconstruct` сохраняются для совместимости. В `HailoEncryptor` и `SoftwareHailoEncryptor` добавлен необязательный keyword `packing`. В HailoEncryptor доступен `cache_affine_lut`; по умолчанию таблица кэшируется. Форматы ключей, сообщений и шифротекстов не изменены.

Численный профиль HEF не меняется: существующее рациональное доказательство ограничивает число активных бинарных входов, а не их соседство. Оно покрывает любые позиции среди первых N каналов при <=16 единицах и нулевом padding. Поэтому новые кадры допускаются прежним доказательством; численные границы не ослаблены и перекомпиляция не требуется. Повторная проверка сохранена в `results/optimization-2026-11-08/n17-packing-proof.json` и `n107-packing-proof.json`.

Affine-параметры читаются при открытии сессии. Точная рациональная LUT из 256 элементов создаётся один раз при включённом кэшировании; в контрольном режиме пересоздаётся при каждом inference. Оба режима используют одинаковое целочисленное восстановление и отклоняют выходы вне 0..16.

В статистику добавлены `affine_encode_ns`, `sdk_call_with_io_ns`, `affine_decode_ns`. Существующий `inference_with_io_ns` сохраняет прежнюю границу: подготовка affine, вызов HailoRT с передачей и affine-декодирование вместе. `prepare_ns` — упаковка; `reconstruct_ns` — объединение частичных сумм и финальная редукция; `total_ns` — внешнее полное время шифрования. Медианы отдельных фаз не обязаны складываться в медиану полного времени.

## Проверка на плате

На исходных Hailo-8L / HailoRT 4.23.0 / firmware 4.23.0 успешно прошли все восемь сочетаний: N=17 и N=107 × обе упаковки × оба режима LUT.

Для каждого сочетания проверены >=1000 случайных полиномов, нулевые, базисные, плотные, чередующиеся и полные/хвостовые входы, группы из 15/16/17 ненулевых позиций. Проверены частичные суммы и восстановленное произведение против независимой целочисленной свёртки; одинаковые шифротексты трёх реализаций, кросс-расшифровка пустых/Unicode/бинарных/многоблочных сообщений, три открытия сессии и очистка после контролируемого исключения хоста после inference.

N=17: 1048 проб на сочетание. N=107: 1238 проб на сочетание. В каждом отчёте `hardware_tested=true`, `exact=true`, `status=passed`. Отчёты `*-qualification.json` и общий журнал находятся в `results/optimization-2026-11-08/`. Это проверки конкретных ключей и HEF, а не утверждение о произвольной NTRU-схеме или производственной криптографической защищённости.

## Команды

Из корня проекта, с установленными HailoRT и драйвером:

```bash
.venv/bin/python -m ntru_pytorch hailo-demo \
  --artifact results/admitted-n107-ubuntu-affine-001 \
  --private-key results/compiler-experiments/n107/private.json \
  --packing active16-v1 --report results/new-active-qualification.json

.venv/bin/python -m ntru_pytorch hailo-benchmark \
  --artifact results/admitted-n107-ubuntu-affine-001 \
  --private-key results/compiler-experiments/n107/private.json \
  --compare-variants --runs 20 --warmup 3 \
  --output results/new-packing-comparison \
  --report results/new-packing-comparison-cli.json
```

Сравнение включает четыре Hailo-варианта и повторные SymPy/PyTorch CPU измерения в том же запуске. Входы, ключи, seed и r одинаковы; размеры партии 1/8/32/128 полиномиальных блоков. Перед измерениями каждого варианта проверяется аппаратная точность, шифротекст и расшифровка. Существующие файлы JSON/CSV не перезаписываются. Сырые времена, медианы/p95, число кадров и байт, версии и хеши сохраняются. Ускорение оценивается по полному времени относительно PyTorch CPU; энергия не измеряется.

## Результат N=107
Итоговый запуск: `n107-variants-controlled.json` и `.csv`. Он выполнен после завершения программных тестов, без их параллельной нагрузки. Первый запуск `n107-variants.json` сохранён как пилотный и не используется для выводов о скорости. Случайные полиномы r подготовлены до таймера для всех backend; полное время включает API шифрования с этими явными r, кодирование сообщения и обработку результата. Генерация ключа, r и файловый ввод-вывод в таймер не входят.
Медианы полного времени, мс:
| Блоков | SymPy CPU | PyTorch CPU | Position без кэша | Position с кэшем | Active без кэша | Active с кэшем |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 12.300 | 0.396 | 1.856 | 0.969 | 1.383 | 0.553 |
| 8 | 94.842 | 2.939 | 6.289 | 5.103 | 3.089 | 2.260 |
| 32 | 362.209 | 12.426 | 19.788 | 18.048 | 8.875 | 7.992 |
| 128 | 1446.311 | 42.123 | 72.039 | 70.311 | 30.879 | 30.011 |

Выбран `active16-v1` с кэшированием LUT: он быстрее других Hailo-вариантов на всех измеренных партиях. По сравнению с PyTorch CPU ускорение составляет 1.30× для 8 блоков, 1.55× для 32 блоков, 1.40× для 128 блоков. На одном блоке ускорения нет. Значение по умолчанию API остаётся `position16-v1`; оптимизированный режим выбирается явно.

На 128 блоках прежний некэшированный Hailo-вариант занимает около 72.04 мс, выбранный — 30.01 мс (около 2.40× быстрее). Число кадров уменьшилось с 1792 до 256, суммарный UINT8 payload входа/выхода — с 1 376 256 до 196 608 байт, ровно в 7 раз. Медиана самого SDK-вызова сократилась с 43.56 до 6.37 мс; оставшиеся расходы включают CPU-валидацию, упаковку и восстановление. На одном блоке пересоздание LUT занимало около 0.87 мс, кэшированный decode — около 0.028 мс. Эти фазовые медианы служат диагностикой и не заменяют полное время.

Программная проверка: 66 passed, 1 аппаратный deselected, включая slow-тесты; дополнительно 5 packing-тестов прошли после выделения общего позиционного упаковщика. Ruff и git diff --check прошли. Исходные успешные HEF не менялись. Энергопотребление не измерялось.

## Переход к N=701

Создан отдельный воспроизводимый экспериментальный ключ (seed=20261108) для исторического preset `dead`: N=701, p=3, q=8192, d=55. Это исследовательская NTRUEncrypt-style схема проекта, не реализация стандартизованного NTRU-HRSS KEM.

Подготовка ONNX и 1000 программных полиномов прошли. DFC выполнил native-проверку, калибровку всех 1770 кадров, bit-exact эмуляцию и компиляцию. Измеренная стадия компиляции с размещением: 83.213 с. Численный экстрактор и независимый host-допуск прошли без ослабления границы <1/2; HailoRT подтвердил потоки HEF.

Артефакт: `results/admitted-n701-ubuntu-affine-001`.
HEF SHA256: `a8db2b54e0eb7f519959f808f1c0312bc820567eb5bf95e7a40cc01617b6af63`.
Сборка: `results/build-n701-ubuntu-affine-001`.
Ключи/исходный ONNX: `results/compiler-experiments/n701-active16-2026-11-08/`.

Выбранный режим `active16-v1` с кэшем LUT прошёл аппаратную квалификацию на Hailo-8L: **2500 проб**, включая **1000 случайных полиномов**, точные частичные суммы и восстановленное произведение, шифротексты SymPy/PyTorch/Hailo и кросс-расшифровка пустых, Unicode, бинарных и многоблочных сообщений; три открытия сессии и очистка после контролируемого исключения на хосте. Отчёт: `results/optimization-2026-11-08/n701-active16-hardware.json`, status=passed, hardware_tested=true, exact=true.

Для штатного r с 55 коэффициентами каждого знака новая упаковка использует 8 кадров вместо 88, payload 78 592 вместо 864 512 байт на полином.

Бенчмарк N=701 выполнен отдельным аппаратным запуском с 6 потоками PyTorch, seed=42, 3 прогревами и 20 измерениями. На партиях 1/8/32/128 ускорение относительно текущего PyTorch CPU составило соответственно 1.225×/1.543×/1.553×/1.438×. Повторные 2500 аппаратных проб и кросс-проверки каждой партии прошли. Подробные результаты, холодный старт и сравнение фаз: [hailo-n701-benchmark.md](hailo-n701-benchmark.md). Данные: `results/n701-benchmark-2026-11-08-001/`.

Следующий этап оптимизации CPU завершён двумя аппаратными раундами reference → optimized и optimized → reference. На 128 блоках новый режим сократил полное время примерно с 259 до 104–105 мс, без изменения HEF и числа кадров. По умолчанию сохранён `reference`; новый путь выбирается через `--host-processing optimized`. Квалификация N=17/107/701 прошла. Сводные результаты, подробные фазы и воспроизведение: [hailo-host-processing.md](hailo-host-processing.md).
